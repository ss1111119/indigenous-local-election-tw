# 不分區政黨票（立委）資料說明

**涵蓋 2008、2012、2016、2020、2024 五屆**，投開票所層級。
來源與另兩個資料集相同：中央選舉委員會選舉資料庫 `votedata.zip`
（授權：政府資料開放授權條款第 1 版）。

建置：`python scripts/build_party_list_election.py`

---

## ⚠️ 讀任何數字之前必須先知道的三件事

### 一、這裡的原住民政黨傾向**只涵蓋原住民族地區**

政黨票是全體選民一起投的，沒有按族別分開計票。要從它讀出原住民的傾向，
本專案的作法是只取「原住民佔比夠高的投開票所」，並附上數學上必然的區間。

**那些投開票所只涵蓋一小部分原住民選民，而且不是隨機的一小部分。**
2024 年的分布：

| 該所原住民選民佔比 | 所數 | 原住民選舉人 | 佔全體原住民 |
| --- | ---: | ---: | ---: |
| ≥95% | 90 | 48,091 | **11.0%** |
| 80–95% | 147 | 76,274 | 17.4% |
| 50–80% | 101 | 44,123 | 10.1% |
| 20–50% | 184 | 46,201 | 10.5% |
| 5–20% | 720 | 68,603 | 15.7% |
| **<5%** | 16,443 | 139,482 | **31.8%** |

佔比 ≥80% 的 237 個所**全部在原住民族地區的山地鄉**：
屏東 65、花蓮 47、臺東 40、南投 24、新竹 18、高雄 13、宜蘭 13、
桃園 6、嘉義縣 5、苗栗 4、嘉義市 2。

**都市裡的平地原住民（佔全體約三成）完全在門檻外**，
而極限法對他們給不出有用的界限——佔比 <5% 時區間寬到 0–100%。

所以這些數字可以說是**「原住民族地區的政黨票結果」**，
**不可以**說成「原住民的政黨傾向」。

### 二、界限是算術，不是統計；它只約束一件事

輸出的是「觀察值 ＋ Duncan-Davis 極限」。給定該層觀察到的得票率 `y`
與**投票者**中原住民佔比 `q`，原住民的支持率**必然**落在：

    [ max(0, (y - (1 - q)) / q),  min(1, y / q) ]

這個區間**不依賴任何統計假設**，只依賴算術。但它約束的只有
「非原住民混入」這一件事——**不約束**上面那條地理選擇偏誤。
一個算術上無懈可擊的區間，仍然只是關於那 90 個所的區間。

### 三、涵蓋率與精度是直接的取捨，所以三個門檻都輸出

| 門檻 | 所數 | 涵蓋原住民選舉人 | 國民黨區間寬（2024） |
| --- | ---: | ---: | ---: |
| ≥95% | 90 | 11.0% | 3.0pp |
| ≥90% | 172 | 20.7% | 4.8pp |
| ≥80% | 237 | 28.4% | 7.5pp |

挑一個等於替讀者做決定。⚠️ 實測**點估計幾乎不隨門檻移動**
（2024 國民黨 68.10／67.50／67.18）——這是高佔比層之間一致的證據，
**不證明能推廣到都市**。

## 四份輸出

| 檔 | 列數 | 說明 |
| --- | ---: | --- |
| `cec-party-list-summary-long.csv.gz` | 120,661 | 選舉概況，投開票所層級，含 `p`／`q` |
| `cec-party-list-votes-long.csv.gz` | 1,848,890 | 逐所逐政黨得票 |
| `cec-party-list-seats.csv` | 98 | 逐屆逐政黨的得票率與席次 |
| `indigenous-party-preference-bounds.csv` | 228 | **估計值**，與官方數字分表 |

⚠️ **第四份是估計值，不是開票結果。** 它的每個數值欄都帶
`觀察_`／`下界_`／`上界_` 前綴，每一列都帶產生它的範圍
（門檻、所數、涵蓋率、`p`、`q`）——引用時不可只取數字而不帶範圍。

### `p` 與 `q` 是兩個不同的東西

- `p` = （山原選舉人 ＋ 平原選舉人）／該所選舉人數 — **選舉人**佔比
- `q` = （山原投票數 ＋ 平原投票數）／該所投票數 — **投票者**佔比

**分層篩所用 `p`，算界限用 `q`。** 兩者的差來自兩張票的投票率不同。
實測 ≥95% 層只差 0.4–1.6 個百分點，但**差距小不是可以混用的理由**：
用錯的那個算出的界限仍然長得像界限，不會有任何跡象。

### `原住民可接` 與 `缺席原因`

「該所不在原住民立委檔內」有兩種意思，輸出把它們分開：

| `原住民可接` | `缺席原因` | 意思 |
| --- | --- | --- |
| `true` | 空 | 兩檔都有該所，`p`／`q` 為實測值 |
| `true` | `該所無原住民選民` | `p = 0` 是**量出來的事實** |
| `false` | `所號兩檔對不上` | `p` 是**未知** |
| `false` | `該所選舉人或投票數為 0` | 分母為零 |

判準是**該縣市的反向缺口**：若每一個原住民所都在政黨票檔內，
政黨票檔多出來的所必然沒有原住民選民。

⚠️ **2020 嘉義市的 189 個所屬第二類。** 該市的原住民投票集中在
兩個特設投票所（村里碼 `0999`，實測 `p` 恰為 1.0000），
其餘一般所確實沒有原住民選民。把它們算成缺口會少報可用率
（98.90% vs 實際 100%）。

## 七個來源檔

語意取自壓縮檔內的官方格式文件 `選舉資料庫格式.odt`，**不是由欄位位置推測**。

| 檔 | 欄數 | 說明 |
| --- | ---: | --- |
| `elbase` | 6 | 行政區基本資料 |
| `elcand` | 16 | 候選人基本資料 |
| `elpaty` | 2 | 政黨基本資料 |
| `elprof` | 20 | 選舉概況 |
| `elctks` | 10 | 候選人得票 |
| `elrepm` | 10 | **不分區政黨代表人**基本檔 |
| `elretks` | 5 | **不分區政黨得票**檔 |

後兩個只有不分區與僑居國外國民立委選舉才有，是本專案其他資料集沒處理過的。

### ⚠️ `elrepm` 帶個資，一律不輸出

欄位為政黨代號、排名、名字、性別、**出生日期**、年齡、**出生地**、
**學歷**、現任、當選註記。實測五屆這三欄都有值。
與 `elcand` 同一條紀律：**不進任何輸出**，並有檢查斷言輸出欄名不含這些字樣。

### ⚠️ `elretks` 的第 4 欄是候選人數，不是應選席次

欄位為政黨代號、**第一階段得票率**、**第二階段得票率**、候選人數、當選人數。

- 第一階段 = 佔全部有效政黨票
- **第二階段 = 排除未達 5% 門檻的政黨後重算，這才是席次分配的依據**
- 第 4 欄是該黨名單的長度。2024 年它恰好也是 34（與應選席次同值），
  誤讀不會有任何跡象——語意必須查官方文件

### ⚠️ 得票率合計**不是**恆為 100.0000

各黨比率四捨五入到小數 4 位，加總有捨入殘差。實測十個合計裡有四個不是：

| 屆別 | 第一階段 | 第二階段 |
| --- | ---: | ---: |
| 2012 | **99.9998** | 100.0000 |
| 2016 | **100.0002** | 100.0000 |
| 2020 | **100.0003** | 100.0000 |
| 2024 | 100.0000 | **100.0001** |

處置是具名精確值 ＋ 捨入上界（政黨數 × 0.00005）兩道檢查：
具名值抓任何變動，上界說明那個差為什麼可以接受。

## 兩個會靜默出錯的陷阱

### 一、選區欄必須忽略，但也必須驗

四個帶行政區代碼的檔對這一欄的用法各不相同，而且 2008 與 2012 起不同：

| 檔 | 2008 | 2012 起 |
| --- | --- | --- |
| `elbase` | 全 `00` | 全 `00` |
| `elcand` | 全 `01` | 全 `01` |
| `elprof` | **全 `00`** | 彙總列 `00`、明細列 `01` |
| `elctks` | `01`（另 312 列 `00`） | `01`（另數百列 `00`） |

⚠️ **不忽略這一欄，2008 的 `elctks` 有 22,555 個單位對不上 `elprof`**
（22,581 中只有 26 對上）——而那會表現成「2008 幾乎全部對不上」，不是報錯。

忽略一個欄位**不等於**放棄驗證它：逐檔宣告允許值、出現宣告外的值即中止，
那份宣告才是「可以忽略」的依據。

### 二、政黨代號跨屆不穩定

`elpaty` 五屆合計 390 個代號，其中 **9 個在不同屆對到不同名稱**：

| 代號 | 漂移 |
| --- | --- |
| 79 | 綠黨 → 台灣綠黨 |
| 102 | 洪運忠義黨 → 全民忠義黨 |
| 133 | 紅黨 → 台灣國民會議 → 台灣人權聯盟 |
| 134 | 制憲聯盟 → 大愛憲改聯盟 → 大愛憲改 |
| 166 | 台灣主義黨 → 全民生活政策黨 |
| 189 | 健保免費連線 → 健保免費 |
| 195 | 中華民國臺灣基本法連線 → 制度救世島 |
| 199 | 人民民主陣線 → 人民民主黨 |
| 278 | 泛盟黨 → 臺灣前進黨 |

⚠️ 這些漂移有兩種機制——同一政黨改名，或代號被另一個政黨重用——
而**從這批資料無法判定是哪一種**（要知道政黨登記史）。
**這正是鍵必須含名稱的理由**：兩種解讀下（代號, 名稱）都安全。

⚠️ 代號 `1`（中國國民黨）與 `16`（民主進步黨）五屆穩定，
但那**不是**代號穩定的證據。

## 建置時執行的自我驗證

任何一項不通過即中止。程式裡共 **31 個中止點**。

**讀檔期**

1. 七個檔的欄數**逐列**恰好符合官方格式文件
2. 值內前置單引號的宣告與來源**雙向**核對（實測 7 個檔帶，2016 起無）
3. 逐檔列數與宣告相符
4. 選區欄取值與逐檔宣告相符
5. 路徑不得落在具名排除的 `old/` 目錄

⚠️ 第 2 項刻意**不用嗅探**。嗅探會自動適應任何來源變化，因此永遠不會失敗。

**跨檔對帳**

6. `elprof` 的行政單位鍵（忽略選區欄後）不得重複
7. 政黨票逐所加總 ＝ 該所有效票（五屆皆 0 筆不符）
8. `elctks` 的每個單位都必須存在於 `elprof`，反之亦然
9. 同一屆內一個政黨代號不得對到兩個名稱
10. 跨屆漂移的代號數與具名清單皆須相符
11. `elretks` 的當選人數合計 ＝ 34
12. 兩階段得票率合計與具名值相符，且殘差不超過政黨數 × 0.00005

**原住民佔比**

13. 投開票所層級的原住民選舉人加總 ＝ 山原 ＋ 平原的檔別合計
14. 原住民選舉人總數與宣告相符
15. （政黨票所, 原住民所, 交集）三個整數與宣告相符

⚠️ 第 13 項抓的是**分母算錯**。用「交集後」的數當分母會讓涵蓋率整組偏高。

**極限法**

16. `0 ≤ 下界 ≤ 觀察 ≤ 上界 ≤ 1`
17. **區間寬不超過 `(1-q)/q`**

⚠️ 第 17 項不是多餘的。只驗第 16 項**擋不住把界限放鬆的錯誤**——
把 `(1-q)` 寫成 `(1+q)` 時下界被截斷成 0，含住關係照樣成立。
實測那個變異確實漏掉了，所以另加寬度恆等式。

⚠️ 極限法全程用 `Fraction` 而非 `Decimal`。分子分母本來就是整數票數，
用有理數不會有捨入；改用 `Decimal` 會讓寬度恆等式差 1 ulp 而誤報，
逼人去設容差——**而容差會把「界限真的被放鬆」一起放過**。

**輸出**

18. 任何輸出的欄名都不得含出生日期／出生地／學歷
19. 三張官方表的欄位與 `PARTY_LIST_MANIFEST` 逐欄相符

## 宣告值由 `--census` 產生，不手抄

    python scripts/build_party_list_election.py --census

輸出可直接貼上的常數區塊（`EXPECTED_ROWS`、`EXPECTED_RATE_SUMS`、
`EXPECTED_RETKS`、`EXPECTED_JOIN`、`EXPECTED_INDIGENOUS_ELECTORS`、
漂移代號清單）。來源換版後的正確流程是跑一次 census 再整塊貼上，
**不是逐個改**。

⚠️ census 模式**不讀取任何被它量測的宣告值**，否則檢查會變成自我證明。

⚠️ 這個模式的存在是有代價換來的：實作本資料集時，手抄的宣告值錯了八次，
其中四次的根因是「跑了普查、印出摘要，然後把摘要當成資料」——截斷、
四捨五入、只印一個分母各自銷毀了資訊，而摘要看起來永遠是完整的；
另一次是根本沒量就寫，卻標成「普查值」。

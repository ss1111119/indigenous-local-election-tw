# 中選會↔內政部 行政區代碼對照表 schema

**檔案**：`data/processed/cec-moi-crosswalk.csv`（8,344 列，涵蓋 2014／2018／2022 三屆的行政區）
**建置**：`python scripts/build_crosswalk.py [內政部界圖目錄]`
**回答的問題**：拿本專案的選舉資料，能不能 join 到內政部的圖資與人口統計？

## 結論：能，但**必須用代碼 join，不能用名稱 join**

| 層級 | 對上 | 總數 | 比率 |
| --- | ---: | ---: | ---: |
| 鄉鎮市區 | 368 | 368 | **100%** |
| 村里 | 7,688 | 7,976 | 96.39% |

村里層級對不上的 288 筆全部可解釋（見下）。**代碼層面沒有結構性衝突。**

### 對應規則

官方格式文件已載明，本專案 2018／2022 兩屆資料實測確認：

```
鄉鎮市區   CEC 省市 + 縣市 + 鄉鎮市區              = MOI TOWNCODE（8 碼）
村里       上述 8 碼 + CEC 村里碼去掉第 1 碼        = MOI 村里代碼（11 碼）
```

實例：

```
臺東縣成功鎮      CEC 10,014,__,020  →  10014020   MOI TOWNCODE
新北市板橋區留侯里 CEC 65,000,__,010,0001 → 65000010001  MOI district_code
```

---

## ⚠️ 為什麼不能用名稱 join

**中選會與內政部的行政區名稱都含 Unicode 私用區（PUA）字元**，這是 Big5 遺留問題。
多數字型沒有對應字形，字會看起來憑空消失。

| CEC 原始 | 顯示成 | 內政部 | 說明 |
| --- | --- | --- | --- |
| `下里` | 下里 | `下廍里` | `U+E02D` 即「廍」 |
| `磚里` | 磚里 | `磚\U000fffa8里` | **內政部自己也用 PUA** |
| `南里` | 南里 | — | |

本專案輸出中共有 **8 個不同的 PUA 碼位**，影響 **35 個行政區**
（在 `summary` 表中因跨屆別與選舉種類重複而出現於多列），
以及 **2 個候選人姓名**（`歐中`、`陳吉`——真人姓名）。

這不是本專案的解碼錯誤：已驗到原始位元組層級，`elbase.csv` 內就是
`\xe4\xb8\x8b\xee\x80\xad\xe9\x87\x8c`，中間三個位元組即 `U+E02D`。忠實保留。

**所以：一律用代碼比對。** 需要顯示名稱時，建議改用內政部的名稱（PUA 較少）。

## 村里層級對不上的 288 筆

### 8 筆：中選會自訂代碼（跨村里投開票所）

`比對狀態 = 中選會自訂（跨村里投開票所）`。全部在**連江縣**，
代碼形如 `0A01`、`0A02`，名稱是多個村里以頓號串接：

```
090070100A01  復興村、福沃村
090070100A03  仁愛村、津沙村、馬祖村、四維村
```

官方格式文件說明：跨多個村里的投開票所由中選會另行自訂代碼。
⚠️ 文件寫「第 1 碼為英文」，但實測是 `0A01`——**第 1 碼仍是 `0`，英文在第 2 碼**。
文件在這裡不精確；判斷時請用「去掉第 1 碼後非全數字」。

這些代碼**在內政部不存在也不應該存在**，因為它們是投開票所的編制單位，不是行政區。

### 50 筆：代碼相符但名稱不同

`比對狀態 = 代碼相符但名稱不同`。**代碼是對的**，差異全部來自上述 PUA 字元。
這 50 筆可以正常 join，只是不能用名稱驗證。

### 230 筆：查無對應——**越舊的屆別越多，完全單調**

⚠️ **時間基準不同**：內政部界圖為民國 114/03/18、人口統計為 115/06，
而選舉是 2014、2018、2022 年的 11 月。期間的行政區改制、村里整併
會讓舊屆的村里在現行清單中查無對應。

三屆資料實測，模式完全單調：

| 出現屆別 | 筆數 | 佔比 |
| --- | ---: | ---: |
| **只在 2014** | **183** | **80%** |
| 2014 ＋ 2018 | 44 | 19% |
| 只在 2018 | 1 | |
| 2018 ＋ 2022 | 1 | |
| 三屆都有 | 1 | |
| **只在 2022** | **0** | **0%** |

**距今越久，對不上的越多；沒有任何一筆是 2022 獨有的。**
這正是「行政區改制」而非「代碼規則有誤」的證據——若是規則問題，
不會與屆別新舊呈現這種單調關係。

本專案未逐筆查證改制紀錄，僅標記狀態供使用者自行判斷。

這也意味著：**要做跨屆的空間分析，必須自行處理行政區改制**，
不能假定同一個村里代碼在不同屆別指的是同一塊地方。

## 欄位

| 欄 | 說明 |
| --- | --- |
| `層級` | `鄉鎮市區` 或 `村里` |
| `cec_省市`／`cec_縣市`／`cec_鄉鎮市區`／`cec_村里` | 中選會代碼，與三張長表的同名欄位對應 |
| `cec_名稱` | 中選會的名稱（**可能含 PUA**） |
| `moi_代碼` | 內政部代碼；查無對應或自訂代碼時為空 |
| `moi_名稱` | 內政部的名稱（**也可能含 PUA**） |
| `moi_縣市` | 內政部的縣市名稱，由代碼前 5 碼查得 |
| `比對狀態` | `完全相符`／`代碼相符但名稱不同`／`中選會自訂（跨村里投開票所）`／`查無對應` |
| `名稱含私用區字元` | `Y`／`N`。為 `Y` 者不可用名稱 join |

## 內政部來源

本專案**未自行下載**這些檔案，來自相鄰專案 `indigenous-constitution-tw`：

| 檔 | 用途 | 基準日 |
| --- | --- | --- |
| `moi-township-boundary-1140318.zip` | 鄉鎮市區代碼與名稱 | 民國 114/03/18 |
| `moi-county-boundary-1140318.zip` | 縣市代碼與名稱 | 民國 114/03/18 |
| `moi-odrp013-population-by-indigenous-status-11506.json` | 村里代碼與名稱 | 民國 115/06 |

因非本專案下載且合計約 16MB，**不納入本版本庫**；入庫的是本腳本的產出。
要重新建置請指定其所在目錄：`python scripts/build_crosswalk.py <目錄>`。

## 建置時的自我驗證

**鄉鎮市區層級必須 100% 對上**，否則中止——若這條不成立，代表
「CEC 省市+縣市+鄉鎮市區 = MOI TOWNCODE」的前提已改變，
整份對照表的基礎就沒了，不該輸出半套結果。

村里層級不設硬性門檻，因為時間基準差異造成的少數不符是預期內的，
但每一筆都會標上 `比對狀態` 供使用者自行判斷。

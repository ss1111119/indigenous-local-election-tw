s = pd.read_csv("data/processed/cec-local-election-summary-long.csv.gz", dtype=str)

## ⚠️ 讀之前必須知道的七件事

### 一、`層級` 欄決定一切，沒有它就別加總

原始檔把**彙總列與明細列混在同一個檔案裡**。直接對得票或票數加總，
數字會暴增數倍——因為每一票被算了好幾次（投開票所一次、村里一次、
鄉鎮市區一次、選舉區一次⋯⋯）。

`層級` 欄是本專案依官方格式文件的補零規則算出來的，值有六種：

| 層級 | 意義 |
| --- | --- |
| `檔別合計` | 該檔案範圍的總計（**不是全國**，見第二點） |
| `直轄市縣市` | 縣、省轄市或直轄市 |
| `選舉區` | 該縣市內的選舉區 |
| `鄉鎮市區` | |
| `村里` | |
| `投開票所` | 最細一層 |

**要加總請先篩層級，而且要同時篩選舉種類。**

### 二、`檔別合計` 不是全國——`city` 與 `prv` 要相加

T2／T3／T1 分成兩份檔案，兩者是**互斥的行政區劃分**：
`city` 是縣與省轄市，`prv` 是六都（臺北、高雄、新北、臺中、臺南、桃園）。
D2／R3／R2 只有一份，`檔別` 標記為 `單一`。

各選舉種類的全國數字（`city` ＋ `prv` 相加）：

| 種類 | 選舉人數 | 投票數 | 投票率 | 候選人 | 當選 | 其中婦女保障 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| T2 平地原住民議員 | 202,477 | 106,573 | 52.63%* | 73 | 34 | 0 |
| T3 山地原住民議員 | 216,262 | 144,164 | 66.66%* | 80 | 35 | 0 |
| D2 原住民區長 | 31,807 | 23,712 | 74.55% | 20 | 6 | 0 |
| R3 原住民區民代表 | 31,803 | 23,712 | 74.56% | 92 | 50 | 0 |
| R2 鄉鎮市民平原代表 | 91,627 | 55,614 | 60.70% | 134 | 72 | **2** |
| T1 區域議員（對照組） | 18,710,006 | 11,445,404 | 61.17%* | 1,524 | 841 | **4** |

＊有 `city`／`prv` 兩份者，全國投票率為**本專案計算值**（合計投票數／合計選舉人數），
原始檔中不存在這個數字。單一檔者則直接取自原始檔。

### 三、⚠️ T2／T3 有將近四成是「全零列」

`summary` 表 267,876 列中有 **60,914 列（22.7%）** 是全零列——
`有效票`、`無效票`、`投票數`、`選舉人數`、`人口數` 全部為 0。

**它們全部集中在 T2 與 T3：**

| 種類 | 全零列 | 該種類總列數 | 佔比 |
| --- | ---: | ---: | ---: |
| T2 議員(平地原住民) | 8,932 | 23,180 | **38.5%** |
| T3 議員(山地原住民) | 8,199 | 21,475 | **38.2%** |
| D2／R3／R2／T1 | 0 | — | 0% |

原因：平地／山地原住民選舉人**散布在整個縣市的每一個投開票所**，
而多數投開票所根本沒有這類選舉人。那些單位仍會出現在檔案裡，但數字全為 0。
D2／R3／R2 侷限在特定的原住民區或鄉，T1 涵蓋所有選民，所以都沒有這個現象。

**這會影響什麼：**

```python
# ❌ 錯——分母含了 8,173 個沒有平地原住民選舉人的投開票所
t2 = s[(s["選舉種類"] == "T2") & (s["層級"] == "投開票所")]
t2["選舉人數"].astype(int).mean()          # 12.59（n=16,086），低估一半

# ✅ 對——先排除全零列
real = t2[t2["選舉人數"].astype(int) > 0]
real["選舉人數"].astype(int).mean()        # 25.59（n=7,913）
```

要數「有多少個投開票所」「平均每所多少選舉人」「有多少個村里」這類問題，
**一律先篩掉 `選舉人數 == 0` 的列**。要算總數（總投票數、總選舉人數）則不必，
因為零加上去不影響。

建置時會驗證「選舉人數為 0 的列必須整列為 0」——若出現「沒有選舉人卻有票」即中止。

### 四、⚠️ 不同選舉種類之間**不可相加**

這是最容易犯的錯。**D2 與 R3 是同一批選民**——實測投票數皆為 23,712，
選舉人數 31,807 與 31,803 只差 4 人。他們是那六個原住民區
（高雄市茂林、桃源、那瑪夏；新北市烏來；臺中市和平；桃園市復興）的居民，
同一天投了區長票與區民代表票兩張。

把各種類的選舉人數相加會嚴重重複計算。同理，T2 與 T3 的選民雖然互斥
（平地原住民與山地原住民身分二選一），但把他們跟 T1 相加也沒有意義——
原住民選民同時也是區域議員的選舉人。

**每個選舉種類請各自分析。** T1 放進來是作為對照組，不是要加總的。

### 五、當選人不是只有 `*`

原始檔的當選註記有**四個值**（官方格式文件明定），本表保留原值於
`當選註記`，並提供已解讀的 `當選註記語意`：

| 原值 | `當選註記語意` | 來源認定為當選？ |
| --- | --- | --- |
| `*` | 當選 | 是 |
| （空白） | 未當選 | 否 |
| `!` | **婦女保障當選** | **是** |
| `-` | 因婦女保障被排擠未當選 | 否 |

**只數 `*` 會系統性少算當選人，而且不會報錯。** 2022 年共有 **6 席**
是婦女保障當選：R2 兩席（臺東縣卑南鄉第 03 選舉區、花蓮縣光復鄉第 04 選舉區）、
T1 四席。

⚠️ **但不要用註記算席次——請用 `當選` 欄。** 上表是「來源怎麼認定」；
`當選` 是跨檔比對後的權威判定，兩者在 63 筆上不同（見下方欄位表的警告）。
健康屆別完全一致，所以只用註記算在多數屆別看起來是對的——那正是它危險的地方。

⚠️ **本專案先前誤稱資料中未出現 `-`。** 實際上 2014 年有 12 筆、2018 年有 8 筆、2009–2010 年有 16 筆，共 36 筆。全部為男性，且全部計為未當選。
35 個出現 `-` 的選舉區**全部同時出現 `!`**（配對出現）；另有 6 個選舉區只有 `!` 沒有 `-`。

### 六、行政區代碼一律是字串，不要轉成數字

`省市`／`縣市`／`選舉區`／`鄉鎮市區`／`村里`／`投開票所` 六欄都是字串：

- **補零形式本身帶語意**：`000` 代表「該層級以上的彙總」，轉成數字就沒了
- **村里代碼首碼可能是英文**：官方格式文件說明，跨多個村里的投開票所
  由中選會另行自訂代碼（如 `A001`）。本次資料 0 列，但解析器仍支援

讀取時請用 `dtype=str`。

### 七、候選人資料已做個資最小化

原始 `elcand.csv` 含**出生日期、出生地、學歷**。中選會〈網站資料開放宣言〉
明訂：個人資料能否蒐集處理利用，使用者須自行依個人資料保護法辦理——
開放授權不免除這一條。

因此本表**不輸出**這三欄。保留的是：

- `姓名`——公職候選人姓名屬選舉公開資訊，且是識別候選人的必要欄位
- `性別`、`年齡`、`現任`、`政黨`——分析參選結構所需，識別性遠低於出生日期

要這三欄請自行回原始壓縮檔取用，並自行承擔個資法上的責任。

### 三張表共用的可比性標記欄位

資料橫跨九屆之後，職位、類別粒度與行政區代碼系統都不再一致。
**下游不該靠讀這份文件來過濾資料**，所以這些判斷直接標在每一列上：

| 欄 | 值域 | 說明 |
| --- | --- | --- |
| `office_type` | `縣市議員`／`直轄市議員`／`臺灣省議員`／`直轄市原住民區長`／`直轄市原住民區民代表`／`鄉(鎮、市)民代表` | T1／T2／T3 的職位取決於檔別（`city` 是縣市、`prv` 是直轄市） |
| `category_granularity` | `分平地山地`／`合併未分平地山地`／`不分平地山地（原住民區）`／`非原住民選舉種類（對照組）` | ⚠️ `合併未分平地山地` 者與 T2／T3 粒度不同，不可混計 |
| `is_main_sequence` | `true`／`false` | **能不能畫進跨屆折線。** 僅官方選舉種類為 `true`；三個自訂代碼為 `false`（共 39 列） |
| `admin_code_system` | `1994`／`1998`／`2002`／`2005+`／`2009`／`2014+` | 行政區代碼系統，六套**互不相通**。跨屆比對行政區前必須先確認此欄相同 |
| `縣市_正規化` | 3 碼 | **跨檔比對縣市請用這一欄，不要用 `縣市`。** 1998／2002 的原住民分項檔縣市代碼在各檔內部重新編號，此欄已換算為同屆「區域」檔口徑 |
| `鄉鎮市區_正規化` | 3 碼或**空字串** | ⚠️ **空字串代表「該檔的鄉鎮市區代碼是檔內重編、本專案未正規化」，不是資料缺漏。** 1998／2002／2005 的原住民分項檔皆為空。刻意留空而非放原始碼——放原始碼會讓 `(縣市, 鄉鎮市區)` 的 join 成功執行但**對錯行政區** |

⚠️ **「2005 起才是全域代碼」只在縣市層級成立。** 2005 的縣市碼與同屆區域檔
12/12 相同，但鄉鎮市區碼仍是檔內重編（山原 153/226、平原 76/224 對不上）。

### `cec-local-election-candidates-long.csv`（7,818 列）

候選人，來自 `elcand.csv` ＋ `elpaty.csv`。

| 欄 | 說明 |
| --- | --- |
| `號次`、`姓名` | `姓名` 部分含族語名（如 `孫湯玉惠 aly saku`），與漢名同欄 |
| `政黨代號`、`政黨名稱` | 已對照 `elpaty.csv`；`999` 為「無黨籍及未經政黨推薦」 |
| `性別` | 已由 `1`／`2` 解讀為 `男`／`女` |
| `年齡`、`現任` | ⚠️ **`年齡` 是乾淨值，不是來源原樣**——有記載放值、未記載留空。直接跑 `AVG(年齡)` 就會得到正確答案（實測 n=7,335、平均 **50.80**）。`0` 與 `99` 的處置不對稱：`0` 不可能是真實年齡，任何屆別都留空；`99` 落在合法值域內，只在具名的 1994／1998／2002／2005／2006 五屆留空，否則將來真有 99 歲候選人時會吃掉真值。⚠️ **乾淨不等於正確**：只保證不含哨兵值，不保證年齡本身正確 |
| `年齡_原始` | **來源原樣，含無資料值。** 原始檔說明年齡可能為 `0` 或 `99`（無資料）——實測那五屆共 483 位候選人整批是 `99`，2009-2010 以後四屆從未出現 `99`（範圍 23–89），全資料的 `0` 出現 0 次。對這一欄跑 `AVG()` 會把 483 個 `99` 當成年齡，平均變成 53.78（n=7,818）|
| `當選註記`、`當選註記語意` | 見第五點。⚠️ **這兩欄反映「來源怎麼寫」，含來源的已知錯誤**——見下方警告 |
| `當選` | `Y`／`N`。**跨檔比對後的權威判定。算席次直接用這一欄，不必先讀文件** |
| `當選_依據` | 權威值取自 `elctks` 的哪一個層級（`elctks_選舉區`／`elctks_鄉鎮市區`／`elctks_檔別合計`）。保留依據而非只留布林值——727 筆取自鄉鎮市區層級、10 筆取自檔別合計，依據較弱 |

⚠️⚠️ **`當選註記` 與 `當選` 的分工，用錯會算錯席次。**

`當選註記` 是來源原樣，**會忠實反映來源的錯誤**。以它推導席次（`*` 或 `!` 計為當選）
實測有兩處損壞：

| 檔 | 由 `當選註記` 算出的席次 | 正確席次（`當選`） |
| --- | ---: | ---: |
| 2005 縣市議員／山原 | **18** | **30** |
| 2005 縣市議員／平原 | **20** | **27** |
| 1994 直轄市原住民（高雄市） | 標錯人（吳福祥 252 票） | 高玉生（481 票，該市最高票） |

不符的 63 位候選人在建置腳本中**逐一具名**，不是整檔放行；
不符集合必須恰好等於具名集合，多一筆少一筆都中止建置。

依專案紀律**不覆寫來源數字**，所以來源的認定原樣保留在 `當選註記`
（原值）與 `當選註記語意`（解碼），沒有被權威值蓋掉。
健康屆別兩者與 `當選` 完全一致（既有四屆 7,335 筆零不一致）。

⚠️ **此表的欄位數在 2026-08-21 由 29 變 28**（`elected_authoritative` 併入 `當選`，
`elected_authoritative_basis` 更名為 `當選_依據`）。
**不可用位置索引取值**——少一欄會使其後所有欄位左移一格，
依位置讀取的程式不會收到任何錯誤訊息，只會拿到下一欄的字串。請一律用欄名。
同時注意 `當選` 這個欄名在該日之前存的是**來源認定**，語意不同。

各選舉種類候選人數（九屆合計）：T2 504、T3 567、D2 59、R3 284、R2 383、
T1 5,970、T-COMBO 41、T-PRV3 5、T-PRV2 5。

## 建置時執行的自我驗證

任何一項不通過即中止。輸出先全部算完、驗完，才**一次性替換**。
程式裡共 **58 個中止點**，分四個階段。九屆 46 個檔別的實測規模逐檔寫在
`data/processed/validation-report.json`，本節的每個數字都可由該檔重算。

### 一、讀檔期（`process_one`，組裝前）

1. 每個檔的欄數**逐列**必須恰好符合官方格式文件（`elbase` 6／`elcand` 16／
   `elpaty` 2／`elprof` 20／`elctks` 10）。只驗「至少幾欄」會讓多出的欄位靜默通過
2. 用 `csv.reader` 而非 `split(",")`。官方文件要求資料內容不得含逗號，
   但那是對提供端的要求，不是對讀取端的保證
3. `elprof` 的檔別合計列（前 6 欄皆為 0）必須**恰好一列**——沒有或多列都中止
4. `elctks` 的當選註記只能是官方定義的四個值，出現未知值即中止
5. **選舉區欄的允許值逐檔宣告**。舊屆各檔對這一欄的用法不一致（同一屆的
   `elprof` 與 `elcand` 可能各說各話），出現宣告以外的值即中止
6. 關聯鍵的尾隨空白正規化**只作用於宣告的鍵欄**，不對整份資料 strip——
   非鍵欄的來源值一律原樣保留
7. 縣市代碼三段式換算（1998／2002）：對照表必須存在且有資料列，
   換算所依據的三方名稱必須一致

### 二、當選權威值的推導（`derive_elected_authoritative`）

`當選` 欄存放**由 `elctks` 推導的權威值**，不是 `elcand` 的原始認定——
2005 的 `elcand` 當選註記已損壞。詳見「五、當選人不是只有 `*`」。

8. 取**最高層級**的註記；同層級出現互相矛盾的註記即中止，不取「任一為星號」
9. `elctks` 完全沒有對應列時中止，不靜默回傳「未當選」
10. 忽略選舉區欄配對時，候選人身分（省市＋縣市＋鄉鎮市區＋村里＋號次）仍須唯一

### 三、年齡哨兵（`check_age_sentinel`）

11. 哨兵屆別**逐屆宣告**，不用全域規則；列入的屆別必須整批都是無資料值
12. 未列入的屆別不得出現哨兵值——出現即代表宣告已過期

### 四、跨檔對帳（`cross_validate`）

**結構層**

13. `elprof` 的行政單位鍵（6 碼）不得重複——重複列會讓後續所有加總驗證失去意義
14. 候選人複合鍵（行政區 ＋ 號次）不得重複
15. `votes` 的（行政單位 ＋ 號次）必須唯一——重複列會被靜默加總兩次
16. 縣市代碼對照表不得有從未被使用的列。⚠️「用過」的判定範圍必須含 `elbase`：
    1998 平原檔的嘉義縣只出現在 `elbase`，只看 `elprof`／`elcand` 會誤判為多餘

**數值層**

17. `有效票 + 無效票 = 投票數`（逐列）
18. 票數欄不得為負（`summary` 與 `votes` 皆檢查）
19. `投票數` 不得大於 `選舉人數`；**`選舉人數` 為 0 的列必須整列為 0**——
    否則「投票數 ≤ 選舉人數」會因 0 而整條跳過。具名例外 1 筆，
    且該例外的**上層級**另有補償檢查（上層級也異常則中止）
20. `投票率 = 投票數 / 選舉人數` 重算後 ＝ 原始檔的值。**逐列且精確相等，不設容差**：
    中選會用四捨五入（`ROUND_HALF_UP`），不是 Python `round()` 的銀行家捨入。
    九屆共驗 **206,959 列**；改用銀行家捨入，光 2022 一屆就有 47 列差 0.01
    （如 17/32 = 53.125 → 53.13 vs 53.12）。慣例已確認，設容差只會讓真錯誤藏在容差裡

**跨檔層**

21. `elprof` idx11–16 通過「男＋女＝合計」。兩種版面皆不通過即中止；
    **兩種同時通過也中止**（例如全為 0 時），不可靜默採用第一種
22. `elcand` 的實際列數 ＝ `elprof` 的候選人數
23. `elcand` 中當選的列數 ＝ `elprof` 的當選人數
    （**這一項會抓到「只數 `*` 漏掉 `!`」**——實測 R2 會報 72 vs 70）
24. 權威值與 `elcand` 的 `當選` 必須一致，除具名的已知異常
25. **逐一行政單位**：該單位所有候選人的得票加總 ＝ `elprof` 同單位的有效票。
    九屆共比對 **267,481 個單位**（2022 單屆 71,631）。⚠️ 早期版本只比對**總和**，
    那會放過互相抵銷的錯誤（A 少 10 票、B 多 10 票，總和照樣通過）
26. 鄉鎮市區被配錯選舉區的具名選舉區，其鄉鎮市區層級改由兩項補償檢查驗證：
    `elprof` 與 `elctks` 的有效票**多重集合必須相同**，且**代碼集合的差異必須具名**
27. **候選人與得票的雙向參照完整性**：每位候選人至少要有一筆得票列，
    且每個得票鍵都要對應到候選人。候選人的行政區粒度隨選舉種類而異
    （T2／T3／T1 記在選舉區層級，D2／R3／R2 記在鄉鎮市區層級），
    **粒度由資料推導，不寫死種類**
28. `elcand` 與 `elctks` 的當選註記必須一致。比對用的鍵**要套用選舉區正規化**——
    不套用的話，四個選舉區欄不一致的直轄市檔每一列都變唯一，這條檢查等於空轉
29. `elctks` 出現的每個行政單位都必須存在於 `elprof`。`elctks` 比 `elprof` 更細的
    孤兒層級另有三項：向上加總必須等於父層級有效票、父單位必須存在、
    且該層級必須**真的比 `elprof` 最深層級更深**
30. `city` 與 `prv` 的縣市代碼不得重疊——**按選舉種類分組、組內全配對比較**
31. **行政區名稱查無次數會寫進報告**，不再靜默回傳空字串——九屆共 787 次。
    最大一筆是 2014 年 D2 的 417 次：`elbase` 全部 48 列選舉區欄都是 `00`，
    但 `elprof` 有 90 列是 `01`，**來源自身不一致**，查名稱必然落空。
    這些查無先前完全沒有跡象

### 來源瑕疵一律具名，不覆寫

對不上的來源數字**保留原值**，把該筆列進具名清單，並另立補償檢查。
目前具名 **78 筆**：

| 具名清單 | 筆數 | 分布 |
| --- | ---: | --- |
| 當選註記與權威值不一致 | 63 | 2005（61）、1994（2） |
| 候選人得票加總 ≠ 有效票 | 7 | |
| 投票率與原始檔不符 | 7 | |
| 投票數 > 選舉人數 | 1 | |

清單**少一筆或多一筆都中止**——清單過期本身就是錯誤，
「來源修好了」與「檢查失效了」在數字上長得一樣。

## 測試

`python scripts/test_build_local_election.py`（也可用 pytest）跑 **415 項、21 組**：

- **單元**：層級判定、版面偵測、CSV 讀取、關聯鍵正規化、當選權威值推導、
  年齡哨兵、縣市代碼三段式換算、自訂選舉種類代碼、人口數適用層級、
  欄位 oracle 宣告、gzip 可重現性
- **整合**：1994／1998／2002／2005／2006 六個舊屆檔跑完整管線
- **迴歸**：2009-2010／2014／2018／2022 四屆的實際輸出釘死
  （列數、層級分布、逐種類全國數字、婦女保障席次）

**每一條檢查都配一個變異，確認測試真的會失敗。**
`python scripts/mutate_build_local_election.py` 跑 **59 個變異，全部被偵測**，
另含基準對照（未變異的副本必須通過、且不得有測試被跳過）
與變異字串唯一性自我檢查。

變異測試抓到的多半是**驗證本身的漏洞，不是資料的問題**。三個代表性的例子：

| 變異 | 原本的下場 | 修正 |
| --- | --- | --- |
| `city`／`prv` 檢查不按種類分組 | **沒被抓到**——原本寫死 `sets[0] & sets[1]` 只比前兩份，而那剛好就是同種類的 `city`／`prv` | 改為組內全配對 |
| 驗證 23 改成數權威值而非來源註記 | **沒被抓到**——兩側同源後恆成立，`elcand` 從此損壞也偵測不到，且不會有任何錯誤訊息 | 改回數來源的註記 |
| 驗證 28 的鍵不套用選舉區正規化 | **沒被抓到**——它讓檢查恆為真而不是移除檢查，「中止／不中止」測不到 | 改為斷言正規化前後的鍵集合大小不同 |

⚠️ 第三種最難察覺：**檢查沒有消失，只是變成空轉**。
對這一類，只斷言「建置有中止」是無效的——必須斷言一個會因變異而改變的值。

⚠️ 另有十項檢查在 2026-08-22 之前從未被任何測試觸發過。插樁量測顯示
它們**全部執行過（到達 1–20 次）、只是條件從未成立**——不是死碼，
是這批資料剛好沒發生。已全部補上合成髒資料（`test_unguarded_source_checks`），
一項都沒刪。作法是取真實資料深拷貝後改一格，並斷言錯誤訊息含
**只有該檢查會輸出的字串**——只斷言「有中止」證明不了打中的是哪一條。

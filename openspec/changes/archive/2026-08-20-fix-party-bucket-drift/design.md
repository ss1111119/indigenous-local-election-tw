## Context

站台的圖表把政黨分成四桶：中國國民黨、無黨籍及未經政黨推薦、民主進步黨，其餘歸「其他」。分桶目前用**政黨名稱字串**比對。

無黨籍在中選會來源裡有兩套完全不重疊的編碼：

| 政黨代號 | 政黨名稱 | 出現屆別 | 列數 |
| --- | --- | --- | --- |
| `99` | 無 | 1994／1998／2002／2005／2006 | 151 |
| `999` | 無黨籍及未經政黨推薦 | 2009-2010／2014／2018／2022 | 2,894 |

因為只比對名稱，站台上五個舊屆的「無黨籍」全部顯示為 0（1998 T2 的常數即為 `[0, 0]`），151 位候選人、25 席被歸進「其他」。既有的 `--check` 抓不到，因為它驗的是「由現有資料重建的常數 == 網頁現況」，而那五個舊屆沒有可比對的基準。

同一個錯誤有第二個現場：`docs/roster.html` 有一個手寫死的 `MAIN` 物件（不在腳本產生的 `D` 常數內），同樣只認「無黨籍及未經政黨推薦」，所以舊屆的無黨籍當選人在名錄裡拿到「其他」的灰色徽章。

另外，「無黨籍」目前使用橘色，而橘色在臺灣政治語境中是親民黨的顏色。親民黨確實出現在這份資料裡：128 位候選人、40 席、橫跨 2002 至 2022 七屆，且是「其他」桶中最大的一個（「其他」合計 815 位候選人、170 席）。

## Goals / Non-Goals

**Goals:**

- 讓「無黨籍」在九屆每一屆都正確計入，不再有五屆顯示 0。
- 讓分桶決策只有**一個**來源，不再散落在 Python 與手寫的 HTML 常數兩處。
- 讓這一類「跨屆同一實體被當成兩個」的錯誤在下次發生時會被測試擋下。
- 讓配色不再把某個政黨的顏色指派給不是它的類別。

**Non-Goals:**

- **不新增第五桶**（例如把親民黨獨立出來）。見決策 5。
- **不做政黨的歷史沿革合併**（改名、分裂、合併）。同代號多名稱者一律視為不同實體，除非另有具名證據。
- **不改動長表的產出。** 建置腳本與三張長表完全不動，本變更只在站台產生端。
- **不重新設計圖表。** 只調整顏色指派與非顏色編碼的補強，不改圖表種類或版面。
- 不處理 `historical-terms-1994-2006` 那份 spec 的 Purpose 佔位文字，本變更不碰該能力。

## Decisions

### 1. 分桶的鍵是 `(政黨代號, 政黨名稱)` 配對，寫成具名對照表

- **Rationale:** 兩種單一鍵都不成立，這是實測出來的：
  - **只用名稱**（現況）→ 無黨籍破掉。代號 `99`「無」與代號 `999`「無黨籍及未經政黨推薦」是同一件事的兩套寫法，出現屆別完全不重疊。
  - **只用代號** → 民進黨破掉。舊屆是 `2`、新屆是 `16`，但名稱一致，所以現行的名稱比對對民進黨反而是對的。國民黨兩個時代都是 `1`。
  - 其他同名多代號者：新黨 `5`／`74`、親民黨 `3`／`90`、台灣團結聯盟 `4`／`95`、無黨團結聯盟 `7`／`106`、勞動黨 `15`／`33`。
  - 同代號多名稱者：`303` 基進黨／台灣基進，以及代號 `290`、`166`、`199`、`254`。
- **Decision:** 建立 `PARTY_IDENTITY_BUCKETS`，鍵為 `(政黨代號, 政黨名稱)` 的字串配對，值為桶名。初始內容恰為五筆：`("1", "中國國民黨")`、`("2", "民主進步黨")`、`("16", "民主進步黨")`、`("99", "無")`、`("999", "無黨籍及未經政黨推薦")`。未列入者一律歸「其他」。
- **同代號多名稱不自動合併**：`303` 的兩個名稱是兩個不同的鍵，各自查表，都查不到就都歸「其他」。這是刻意的——代號被回收再發給另一個政黨時，自動合併會造成無聲的錯誤歸戶。
- `政黨代號` 必須加入 candidates 長表的必要欄位清單。目前程式沒讀這一欄所以也沒宣告；既有的欄位契約測試會強制這件事（讀了卻沒宣告即失敗）。

### 2. 名錄的 `MAIN` 改為由腳本產生，不再手寫

- **Rationale:** 同一個 bug 有兩個現場。名錄頁的 `MAIN` 是寫死在 HTML 裡的物件字面值，不在腳本產生的 `D` 常數內，同樣只認「無黨籍及未經政黨推薦」。只修 Python 端會留下另一個會再次漂移的複本。
- **Decision:** `MAIN` 改由建置腳本依同一份 `PARTY_IDENTITY_BUCKETS` 產生，以既有的「固定標記行就地替換」機制寫入，與 `DATA`／`D` 同一套做法。名錄端的桶判定因此與圖表端共用單一來源。

### 3. 未列入對照表的身分歸「其他」，不中止；改以具名斷言守住無黨籍

- **Rationale:** 「其他」桶本來就該裝下所有沒有具名的政黨（九屆共 59 個相異名稱），對未知身分中止建置會讓每一次新選舉都需要人工介入，代價不成比例。
- 但這也代表**沒有任何自動門檻抓得到這次的錯**。已實測兩種被提議的統計不變量，都不成立：
  - 「其他桶單一政黨佔該屆總候選人數 < 5%」：今天會失敗（`無` 在舊屆佔 16.7%–60.9%），但**修好之後仍然會失敗**——2002 年「其他」桶最大者變成親民黨，28 / 164 = 17.1%。舊屆規模太小（1994 全屆只有 23 位候選人），固定比例門檻在那裡沒有意義。
  - 「其他桶成員必須小於具名桶」：舊屆的民進黨只有 3 至 7 人，比親民黨少，會誤報。
- **Decision:** 改用**具名的領域斷言**：「無黨籍在九屆每一屆的候選人數都必須大於 0」。這是可查證的領域事實（實測九屆分別為 14、44、50、42、1、567、652、868、807），修正前有五屆為 0，修正後全部非零。另在建置時列印「其他」桶逐屆的組成，讓下一個佔比異常的成員被人看見。

### 4. 無黨籍改用中性深色，橘色不再指派給任何桶

- **Rationale:** 橘色在臺灣政治語境中是親民黨的顏色，而親民黨確實在這份資料裡，目前被歸在「其他」。橘色長條標著「無黨籍」會被誤讀。無黨籍在國際慣例上不使用任何政黨色，用中性色才是誠實的表述。
- **關於色覺辨識的取捨：** 先前選橘色的理由推測是無障礙考量，但這只是推測——專案文件只寫「配色以 CVD 驗證器檢過」，原始碼沒有任何註解說明。拿掉橘色後，藍（國民黨）與綠（民進黨）成為僅有的兩個飽和色，對紅綠色覺障礙讀者較難分辨。
- **Decision:** 顏色的規範**不在本變更定義**，改為服從既有能力 `site-chart-accessibility`（由 change `site-accessibility-baseline` 建立）。本變更只負責「哪個桶用哪個顏色」的指派，可辨識性的門檻與驗證形式一律引用那份 spec：

  - 相鄰配對在正常視覺下 **ΔE ≥ 15**（OKLab ×100），在 protan 與 deutan 模擬下 **ΔE ≥ 8**；明暗主題**各自量測**，暗色主題不得由亮色反推。
  - 「不可把某個實體的慣用色給不是它的桶」這條也已在那份 spec 中（明文寫出 an "other parties" bucket 不得用政黨自己的藍、綠或橘）。
  - 驗證必須記錄而非宣稱，亦由那份 spec 規範。

  因此本變更原本自帶的 `Colour Is Not The Only Encoding` requirement **已刪除**——它與上述三項完全重複，而那份 spec 的版本有可量測門檻，我的只有散文。

- ⚠️ **本變更引入一個那份 spec 尚未量過的配對。** 把無黨籍從橘色改成中性深色之後，「無黨籍」與「其他」（灰）會成為**兩個中性色，只靠亮度區分**——這是整套配色裡最容易糊掉的組合，**必須實測 ΔE，不可目測**。
- ⚠️ **而那個配對在系列順序上並不相鄰。** 順序是 國民黨 → 無黨籍 → 民進黨 → 其他，無黨籍與其他是第 2 與第 4 位。`site-chart-accessibility` 的門檻是對「相鄰配對」下的，**只跑相鄰檢查會完全跳過這一組**，必須以 `--all-pairs` 量全部配對。
- **量測工具為 in-repo 的 `scripts/palette_metrics.py`。** 它列出每個配對的常人／protan／deutan ΔE 並自行判定門檻，未過即非零退出。校準對照外部驗證器：常人差 ≤ 0.04、protan 差 0.01、deutan 差 0.03（做法為 Machado 2009 severity 1.0 矩陣套用在**線性** RGB；套在 gamma 空間會差 0.6~1.2）。
- ⚠️ **`palette_metrics.py` 未實作 tritan。** Viénot 單平面與 Machado 矩陣都與外部驗證器對不上（差 4~18）。因此記錄時只能宣稱 protan／deutan；`site-chart-accessibility` 的門檻本來也只涵蓋這兩種。
- 色差另有 `scripts/test_site_invariants.py` 的 `test_series_palette_separation` 在守。在它加入之前，色差沒有任何測試涵蓋（只守文字對比），把某個系列改成與鄰接系列糊在一起不會被發現。
- ⚠️ **改色途中會有一段測試是紅的。** 改了系列色但還沒重算 `--lab2` 墨色時，`test_in_mark_label_contrast` 會失敗。那是預期的中間狀態，不是新的缺陷——但**不可停在那裡**。
- 橘色空著不指派。這是刻意的：與其把它給一個不擁有它的類別，不如不用。

### 5. 不新增第五桶

- **Rationale:** 兩位外部覆核在這一點上意見相反。贊成方的理由是親民黨跨七屆、40 席、佔「其他」桶當選席次約 24%。反對方的理由是量級：三大桶是 1,116、1,839、1,067 席，親民黨是 40 席，差兩個數量級；而台灣民眾黨 14 席、時代力量 22 席、台灣團結聯盟 22 席與它屬於同一個量級，拉出親民黨就無法解釋為何不拉另外三個。
- **Decision:** 採反對方。「其他」桶內部組成隨時代輪替（台灣團結聯盟 → 親民黨 → 時代力量 → 台灣民眾黨）本身就是資訊，拆出其中一個反而讓那個結構看不見。改以決策 3 的組成列印讓「其他」可被檢視。

### 6. 兩份主 spec 的 Purpose 一併補上

- **Rationale:** 本變更要修改的兩份主 spec，其 `## Purpose` 目前都是歸檔工具留下的 `TBD - created by archiving change ...` 佔位文字。
- **Decision:** 在修改這兩份 spec 時一併把 Purpose 寫成實質內容。第三份能力不在本變更範圍內，維持原狀。

## Implementation Contract

**In scope:** 站台資料產生腳本的分桶與常數產生、其測試與變異測試、兩個 HTML 的配色與 `MAIN` 產生、兩份主 spec、專案說明文件的配色敘述。

**Out of scope:** 長表建置腳本、oracle 模組、三張長表、`historical-terms-1994-2006` spec。

- **Observable behavior:**
  - 概況頁 `DATA` 中，1994／1998／2002／2005／2006 五屆各選舉種類的無黨籍候選人數與當選數不再是 0；對應的「其他」同額減少。
  - 名錄頁的 `MAIN` 由腳本產生，舊屆的無黨籍當選人徽章使用無黨籍的顏色而非「其他」的顏色。
  - 無黨籍的顏色不再是橘色；橘色不指派給任何桶。
- **Interface / data shape:**
  - `PARTY_IDENTITY_BUCKETS: dict[tuple[str, str], str]`，鍵為 `(政黨代號, 政黨名稱)`。
  - candidates 長表的必要欄位清單新增 `政黨代號`。
  - `DATA` 與 `D` 的形狀不變；名錄頁新增一個由腳本替換的 `MAIN` 標記行。
- **Failure modes:**
  - 長表缺 `政黨代號` 欄即中止，由既有的缺欄檢查涵蓋。
  - 任何一屆的無黨籍候選人數為 0 即測試失敗。
  - 名錄頁找不到 `MAIN` 的標記行即中止，不做模糊比對。
- **Acceptance criteria:**
  - `pytest` 通過；「無黨籍逐屆非零」的測試在把 `("99", "無")` 從對照表移除時會失敗。
  - 站台的變異測試腳本所有變異（含本次新增的）全數被偵測到。
  - 執行後以指令讀出兩個 HTML 的常數，斷言五個舊屆的無黨籍候選人數分別為 14、44、50、42、1。
  - 配色的對比與色覺障礙驗證記錄下工具名稱、模擬類型與門檻三項。
- **Scope boundaries:** 見本節開頭的 In scope／Out of scope。

## 歸檔順序（跨 change 的約束）

⚠️ **本變更（`fix-party-bucket-drift`）必須在 `site-accessibility-baseline` 之前歸檔。**

兩者都會寫入 `site-chart-accessibility` 與 `site-data-generation` 兩份主 spec，
**歸檔順序決定最後的 spec 長相**。本變更 11/11 完成後先歸檔，
`site-accessibility-baseline` 後歸檔。

相關的耦合已處理：
- 本變更原本自帶的 `Colour Is Not The Only Encoding` 已刪除，改為服從
  `site-chart-accessibility`，因此兩邊不會在同一條 requirement 上打對臺。
- 該能力候選色表裡「橘色已被無黨籍佔用」那個拒絕理由已由對方改成
  「橘色是親民黨慣用色，不論當下有無其他桶在用都不得指派」——
  本變更釋放橘色後該理由仍然成立。

## Risks / Trade-offs

- **站台數字會變。** 五個舊屆的「無黨籍」與「其他」兩個系列都會改變。這是修正而非資料變動，但既有的 `--check` 會因此報出差異——必須確認那些差異**恰好**是這五屆的這兩個系列，不多不少，否則就是改壞了別的東西。
- **對照表是人工維護的。** 未來新增屆別若又出現第三套無黨籍編碼，仍需要人來加一筆。決策 3 的組成列印是唯一的提示機制，它需要有人去看。
- **拿掉橘色後藍綠並存。** 這對紅綠色覺障礙讀者是真實的代價，靠明度分離與非顏色編碼補償，不是零成本。
- **兩個 HTML 目前有未提交的改動。** 實作前必須確認工作區狀態，否則就地替換會與那些改動衝突。

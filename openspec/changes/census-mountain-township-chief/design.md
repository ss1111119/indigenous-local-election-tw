## Context

本專案已涵蓋 T2／T3 議員、D2 直轄市原住民區長、R3 區民代表、R2 鄉鎮市民代表（平原），但漏掉山地鄉鄉長——地方制度法第 57 條第 2 項規定的法定原住民限定職位。D2 是 2014 年由部分山地鄉改制而來，因此站台上 D2 那條三點序列其實有前身資料存在於來源卻未納入。

要把山地鄉從來源資料裡分離出來，需要一份權威名單，而本專案目前沒有。來源的鄉鎮市長檔案不會標示某鄉是不是山地鄉，只有縣市＋鄉鎮市區代碼；分離只能靠外部名單對應。名單本身會隨行政區改制變動，所以它不是一張靜態表，而是一組帶生效期間的紀錄。

本專案既有的紀律要求：每一份進入 `data/` 的資料都要在 `data/sources.json` 登記出處與授權；跨屆比對一律走 `_正規化` 欄；「未觀察到」與「確認不存在」必須分開記錄。這次清點沿用同一套紀律。

## Goals / Non-Goals

**Goals:**
- 建立一份可查證出處、帶屆別適用範圍的山地鄉名單，落地為 `data/reference/` 下的對照表並在 `data/sources.json` 登記
- 逐屆清點來源壓縮檔內鄉鎮市長資料的結構與可用性，產出書面報告
- 讓「哪些陷阱確認不存在、哪些只是未觀察到」在報告裡是分開的兩類

**Non-Goals:**
- 不新增或修改 `data/processed/` 的任何長表，不新增選舉種類代碼
- 不修改 `docs/` 下任何頁面
- 不計算任何比值或代表性指標
- 不下「應該納入」或「不應納入」的結論
- 不處理平地原住民鄉的鄉長（無同等法定限制，性質不同）

## Decisions

### 山地鄉名單以官方公告為權威來源，並記錄生效期間而非單一快照

名單必須來自官方公告（原住民族委員會或行政院的山地鄉／原住民族地區公告），記錄公告文號、發布日期與生效期間，落地為 `data/reference/mountain-township-list.csv`，欄位至少含：縣市名稱、鄉鎮市區名稱、生效起、生效迄、出處。改制事件（例如 2014 年部分山地鄉改為直轄市原住民區）以「生效迄」表示，不從表中刪除該列。

**替代方案考慮過**：用單一份現行名單套用到所有屆別——否決。1998 年的山地鄉集合與 2022 年不同，用現行名單回推會讓改制前的紀錄對應不到，而且**不會報錯**，只會安靜地少算幾個鄉，正是本專案反覆踩到的靜默失效。

**替代方案考慮過**：從鄉鎮名稱推斷（例如名稱含「山」）——否決，這是猜測不是查證，且必然誤判。

### 清點以「逐屆逐檔開啟並記錄」為準，不從單一屆推論其他屆

對每一個含鄉鎮市長資料的來源資料夾，分別記錄：檔案清單、編碼、`elbase` 的層級結構、選舉區命名方式、能否用縣市＋鄉鎮市區代碼對應到名單、以及對應失敗的筆數與原因。**不以任一屆的結果推論其他屆**——本專案已經證實縣市代碼在 1998／2002／2005 是逐檔重編、立委的縣市代碼 2012 那屆整組不同，抽樣推論在這個資料上已經失敗過。

**替代方案考慮過**：抽兩屆確認可行就宣告全部可行——否決，這正是記憶中「抽樣讓我很有把握地講錯」的模式。

### 陷阱清點區分「確認不存在」與「未觀察到」

報告對每一類已知陷阱（尾隨空白、縣市代碼逐檔重編、鄉鎮市區代碼檔內重編、當選註記損壞）逐屆給出三態之一：確認存在（附具體筆數與樣本）、確認不存在（附如何確認的方法）、未檢查。**不允許把「未檢查」寫成「不存在」**。

**替代方案考慮過**：只記錄發現的陷阱、沒提到的就視為沒有——否決。沉默不等於已驗證，而下一個接手的人無從分辨哪些是查過的。

## Implementation Contract

**行為**：完成後，專案內存在一份可查證出處的山地鄉名單與一份逐屆清點報告，任何人要判斷「山地鄉鄉長資料能不能納入」都有書面依據，不需要重新開啟壓縮檔摸索。

**資料形狀**：
- `data/reference/mountain-township-list.csv`：欄位至少含縣市名稱、鄉鎮市區名稱、生效起、生效迄、出處（公告文號或來源 URL）。改制事件以生效迄標示，不刪列。
- `data/sources.json`：新增該名單的來源登記，含出處 URL、取得日期、授權、性質。
- `docs/schema/山地鄉鄉長資料清點.md`：清點報告。逐屆一節，每節記錄檔案清單、編碼、結構、對應結果（成功筆數／失敗筆數／失敗原因）、四類已知陷阱的三態判定。
- `README.md`：在「尚未解決」區塊更新第 3 點，說明山地鄉鄉長的法源與清點狀態，並指向清點報告。

**失敗模式**：
- 找不到可查證的官方名單公告 → 停止並在報告中明寫「查無官方公告」，不以任何非官方彙整（維基百科、新聞整理）充數，也不自行編纂名單。
- 某屆的資料無法用代碼對應到名單 → 記錄失敗筆數與原因，不推論其他屆同樣失敗，也不推論同樣成功。

**驗收標準**：
- `data/reference/mountain-township-list.csv` 存在，每一列都有非空的出處欄
- `data/sources.json` 含該檔的登記，且既有的來源登記檢查（若有）仍通過
- `docs/schema/山地鄉鄉長資料清點.md` 對每一個含鄉鎮市長資料的來源資料夾都有對應章節，且四類陷阱在每一節都有明確的三態判定，沒有任何一項留白
- 全專案既有測試維持通過：`python scripts/test_build_site_data.py`、`python scripts/test_build_local_election.py`

**範圍邊界**：
- 範圍內：`data/reference/mountain-township-list.csv`、`data/sources.json`、`docs/schema/山地鄉鄉長資料清點.md`、`README.md` 的「尚未解決」第 3 點
- 範圍外：`data/processed/` 下任何檔案、`docs/` 下任何 HTML 頁面、`scripts/` 下任何建置腳本、任何比值或指標計算、納入與否的決定

## Risks / Trade-offs

[查不到官方公告的山地鄉名單] → 依失敗模式停止並明寫查無，不自行編纂。本專案在政府資料授權查證上已有先例：查不到就標記查不到，不用次級來源充數
[名單的生效期間與選舉屆別對不齊（公告日期不等於選舉日期）] → 報告需明寫每一屆用的是哪一份名單、以什麼日期為基準選定，讓判斷可被檢查而不是內建在程式裡
[清點結果誘使順手做納入實作] → 範圍邊界已明列 `data/processed/` 與 `scripts/` 為範圍外；納入是另一個 change，且需先通過選舉期間發布規則的判定

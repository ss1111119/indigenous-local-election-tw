## Problem

名錄頁把 1994、1998、2002、2005、2006 五個屆別的候選人年齡顯示為 **99 歲**。實測：這五屆共 **483 位**候選人的 `年齡` 欄**全部**是 `99`，相異值只有一個；而 2009-2010 以後四屆完全沒有出現過 `99`，實際範圍是 23 至 89 歲。

`99` 是來源用來表示「未記載」的哨兵值，不是年齡。站台目前把它當真值渲染，對 483 個真實的人陳述了假事實（滑鼠提示顯示「男・99 歲」）。

## Root Cause

名錄的候選人 tuple 以 `int(c["年齡"])` 直接取用來源值，沒有判斷該值是否代表「未記載」。

前端模板本身已經能處理缺值（年齡為 0 或空時不輸出「歲」那一段），所以缺的只是「把哨兵值辨識出來」這一步。

這與本變更所屬專案已修過的兩個缺陷同類：來源用某個特定值表示「沒有」，而程式把它當成值。先前兩例分別是「無黨籍在舊屆的政黨名稱是『無』」與「缺屆以 null 表示而非 0」。

## Proposed Solution

在站台資料產生端把哨兵值辨識為「未記載」，**長表維持原樣不動**——來源值不覆寫，只在呈現層省略。

判準**具名到屆別**，不是「99 一律當未記載」：僅對已實測整批為 `99` 的五個屆別生效。若不具名，將來真的出現 99 歲候選人時會被默默吃掉真值。

配兩條會中止建置的斷言：

1. 那五個屆別的 `年齡` 必須**整批**是 `99`（出現第二個相異值即中止——代表該屆其實有真實年齡，具名清單需要重新判斷）。
2. 2009-2010 以後的屆別**不得出現** `99`（出現即中止——代表哨兵值的語意跨屆改變了，或真的有 99 歲候選人）。

## Non-Goals

- **不建立通用的哨兵值登記機制。** 已逐欄掃過候選人長表的 26 個欄位，「舊屆恆定而新屆有變化」的只有兩欄：`年齡`（本缺陷）與 `鄉鎮市區`（恆為 `000`，但 `is_blank` 已視為彙總空值，既有機制已正確處理）。為單一欄位蓋登記表，與本專案已拒絕過的「為空集合建機制」是同一類問題。
- **不修改長表。** 建置腳本與三張長表完全不動；`年齡` 欄在長表中維持來源的 `99`。
- **不推測未記載的年齡**，也不以其他屆別回填。
- 不處理 `性別`、`現任` 等欄位——實測那兩欄在舊屆都有兩個相異值，確實帶資訊。

## Success Criteria

- 名錄頁在 1994、1998、2002、2005、2006 五屆**不顯示年齡**（滑鼠提示只有性別，無「歲」）；2009-2010 以後四屆的年齡顯示不變。
- 把任一舊屆的某一列 `年齡` 改成非 `99`，建置中止並指出是哪一屆。
- 把任一新屆的某一列 `年齡` 改成 `99`，建置中止。
- 三張長表的 `年齡` 欄逐位元組不變。

## Impact

- Affected specs: `legacy-source-quirks`

  ⚠️ 刻意**不**建立 `site-data-generation` 的 delta。哨兵值的辨識、具名與呈現三件事都已由 `legacy-source-quirks` 的三條 Requirement 涵蓋；再寫一條「名錄不得顯示哨兵年齡」會與它重複。前一個變更就發生過重複的 requirement 必須刪掉的情況。

## Context

站台由兩個單檔 HTML 組成：`docs/index.html`（概況圖表）與 `docs/roster.html`（候選人名錄）。兩者各自內嵌一份 JSON 常數（分別是 `DATA` 與 `D`），**由人工維護**——`scripts/` 內沒有任何檔案參照 `index.html` 或 `roster.html`。因此 2026-08-20 資料集擴充至九屆後，站台仍停在四屆。

這不是第一次。commit `aade72f` 修的是同一種不一致。只補資料而不移除手動維護，下一次擴充還會再落後。

新資料同時帶進兩個站台必須遵守的約束：`is_main_sequence`（三個自訂選舉種類代碼不得進入跨屆折線）與 `elected_authoritative`（2005 縣市議員的 `當選` 欄損壞，沿用會少算 19 席）。

## Goals / Non-Goals

**Goals:**

- 兩份站台資料常數改由腳本從 `data/processed/` 的長表產生，不再手抄。
  ⚠️ 實際只需 summary 與 candidates 兩張——站台完全沒有用到 votes 表（名錄的候選人 tuple 是「號次, 姓名, 政黨, 性別, 年齡, 現任, 註記」，不含得票數）。votes 表有 175 萬列／12MB，載入它純屬浪費。
- 腳本先重現現有四屆的數字，差異逐項具名後才擴充至九屆。
- 站台的席次一律採 `elected_authoritative`；跨屆折線一律過濾 `is_main_sequence`。

**Non-Goals:**

- **不改變圖表的種類與版面。** 本次是資料來源與涵蓋範圍的變更，不是視覺重設計。配色、互動、CVD 驗證結果全部沿用。
- **不新增以人口為分母的指標。** `人口數` 欄的底層來源未查證，且適用層級僅到縣市。站台目前完全未使用人口欄，本次維持不使用。
- **不做鄉鎮市區層級的呈現。** 1998／2002／2005 的鄉鎮市區代碼是檔內重編、未正規化（`鄉鎮市區_正規化` 為空），站台不得建立任何依賴該層級的檢視。
- **不改 `docs/三屆概況.md`。** 那份文件明寫範圍為三屆，是獨立的敘述性文件，另議。
- **不引入前端框架或建置工具。** 兩個頁面維持單檔、不連外部資源、淺深色皆可讀。

## Decisions

### 1. 腳本產生，但仍內嵌為常數而非改抓外部檔

- **Rationale:** 站台是 GitHub Pages 的靜態頁，且既有設計明訂「不連外部資源」——改成 `fetch()` 會讓離線開啟與單檔分享失效，也會在 `file://` 下被 CORS 擋掉。內嵌常數這個**形式**沒有問題，有問題的是「由人手維護」。
- **Alternatives Considered:** 改為執行時 `fetch` 長表 CSV。不採納，理由如上；且 votes 表 12MB，前端解析代價過高。
- **Decision:** 腳本讀長表、算出常數、**就地替換 HTML 中的那一行**，其餘 HTML 內容不動。以固定的標記行界定替換範圍，避免正則誤傷。

### 2. 先重現四屆、逐項比對，差異必須具名

- **Rationale:** 這是唯一能同時驗證「腳本算得對」與「站台現有數字對不對」的作法。若直接產生九屆，腳本算錯會與資料擴充混在一起，無法分辨。
- **Alternatives Considered:** 直接產生九屆並人工抽查。不採納——抽查抓不到系統性偏差，而本專案已多次踩到「數字看起來合理但錯」。
- **Decision:** 腳本提供只輸出四屆的模式，與現有常數逐鍵比對。**差異不自動接受**：每一項差異都要查明原因並具名記錄（是站台舊值錯、還是腳本算錯），處理完才擴充至九屆。

### 3. 席次一律採 `elected_authoritative`，名錄的當選標記亦同

- **Rationale:** `當選` 欄忠實反映來源錯誤。2005 山原以 `當選` 算只有 18 席（正確 30）、平原 20（正確 27）。站台呈現的是「誰當選了」，必須用權威值。
- **Alternatives Considered:** 兩個都顯示。不採納——站台的讀者不需要處理來源瑕疵，那是資料層的事；並陳只會讓人不知道該信哪個。
- **Decision:** 所有席次、當選標記、當選人政黨與性別統計一律由 `elected_authoritative` 推導。`當選註記` 仍用於區分婦女保障（`!`）與被排擠（`-`）的呈現。

### 4. 自訂選舉種類代碼不進跨屆折線，獨立區塊呈現

- **Rationale:** 1994 只有 6 席、1998 有 55 席。畫成同一條折線會被讀成參政權在 1998 爆炸性擴張，實際只是壓縮檔內沒有 1994 的縣市議員資料。台灣省議員 1998 年精省後廢除，與縣市議員是不同職位。
- **Alternatives Considered:** 完全不顯示這三種。不採納——資料已收錄，隱藏等於讓讀者以為 1994 沒有原住民民代。
- **Decision:** 折線圖只取 `is_main_sequence` 為 `true` 的資料。三個自訂代碼另以獨立區塊（表格或分離的圖）呈現，並明文標示「已廢除的職位」或「合併類別，未分平地／山地」，以及不可與 T2／T3 相加的理由。

### 5. 缺屆標示為不存在，不以 `0` 填補

- **Rationale:** 以 `0` 填補會讓「該屆沒有這種選舉」與「該屆這種選舉是 0 席」無法分辨。
- **Decision:** 擴充後缺屆的組合大幅增加（例如 D2／R3／R2 在 2009 以前都不存在、T2／T3 在 1994／2006 不存在），一律標示為不存在。常數中以 `null` 表示，站台端：折線圖**留空**（不畫該點）、跨屆表格寫「無此選舉」或「—」、`#t-custom` 逐屆逐列的表格則**不列出該列**。

  ⚠️ **本節原本寫的是「一律以 `×` 標示」，那是錯的。** 站台從未渲染過 `×`——
  `docs/index.html` 內 `×` 只出現在一行註解裡，而那行說的是相反的話；
  `docs/roster.html` 出現 0 次。「沿用既有慣例」的前提本身不成立，
  既有慣例就是「無此選舉」與「—」。README 與 HANDOFF 的同一處敘述已一併更正。

## Implementation Contract

- **Behavior:**
  - 執行 `python scripts/build_site_data.py` 後，`docs/index.html` 與 `docs/roster.html` 的資料常數被就地更新為九屆內容，兩檔的其餘位元組不變。
  - 站台的折線圖只呈現主序列資料；自訂代碼在獨立區塊。
  - 名錄顯示的當選者以 `elected_authoritative` 為準。
- **Interface / data shape:**
  - 新增 `scripts/build_site_data.py`，提供 `--only-existing-terms` 模式輸出僅含現有四屆的常數供比對，以及 `--check` 模式只比對不寫檔。
  - `index.html` 的 `DATA` 維持現有形狀（`types[].years[]` 巢狀、`years` 陣列、`note2009`），新增每個選舉種類的 `mainSequence` 布林欄位。
  - `roster.html` 的 `D` 維持現有形狀（`parties`、`years`、`rows`）。
- **Failure modes:**
  - 長表缺欄（例如找不到 `elected_authoritative`）即中止，不產生半套結果。
  - 重現比對階段若出現未具名的差異即中止。
  - HTML 中找不到界定替換範圍的標記行即中止，不做模糊比對。
- **Acceptance criteria:**
  - 四屆重現模式下，產出的常數與現有站台常數逐鍵相同，或差異已全部具名。
  - `pytest` 通過，含「主序列」與「席次取自權威值」的單元測試，各配變異測試。

    ⚠️ 「主序列**過濾**」不在本腳本內。`build_site_data.py` 只把 `is_main_sequence`
    轉成 `mainSequence` 放進常數；真正的過濾是 `docs/index.html` 的
    `DATA.types.filter(t => t.mainSequence)`。因此測試分兩側：Python 端測**旗標傳遞**
    （函式名為 `test_main_sequence_flag_passthrough`，刻意不叫「過濾」），
    前端那一行以 node 直接執行來測（`test_index_html_filters_custom_types`）。
    只測 Python 端會產生假保障——刪掉前端那一行，Python 測試全綠、站台卻已畫錯。
  - 以瀏覽器開啟兩個頁面，九屆資料正確顯示，缺屆為 `×`，自訂代碼不在折線圖內。
- **Scope boundaries:**
  - **In scope:** 站台資料常數的產生腳本、兩個 HTML 的資料常數與必要的呈現調整（折線過濾、自訂代碼區塊）、README 對站台範圍的敘述。
  - **Out of scope:** 圖表種類與版面重設計、人口相關指標、鄉鎮市區層級檢視、`docs/三屆概況.md`。

## Context

候選人長表的 `年齡` 欄在 1994、1998、2002、2005、2006 五屆整批是 `99`（483 列）。那是來源格式文件明列的無資料值——壓縮檔內的 `votedata/voteData/選舉資料庫格式.odt` 對 elcand.csv 寫著「年齡 Num(3) (部分選舉未必有資料，可能 0 或 99)」。本專案不覆寫來源值，所以長表維持 `99`。

前一個變更 `age-99-is-unrecorded` 已在站台呈現端處理，但那層保護只在站台之內。直接使用長表的人拿不到：對 `年齡` 跑 `AVG()`，實測平均由 **50.80**（n=7,335）被拉高到 **53.78**（n=7,818），差 **2.98 歲**，沒有任何錯誤訊息。

本專案對同類情況已有既定做法——原欄位保留、另加一個可用的衍生欄位：

| 原欄位 | 衍生欄位 | 不可用時 |
| --- | --- | --- |
| `縣市` | `縣市_正規化` | 留空 |
| `鄉鎮市區` | `鄉鎮市區_正規化` | 留空 |
| `當選註記` | `elected_authoritative` ＋ `_basis` | 不適用 |

`年齡` 沒有跟上。

## Goals / Non-Goals

**Goals:**

- 直接使用長表的人**在最直覺的欄位名下**就拿到可以放心聚合的年齡。
- 未記載的判準只有一個實作，站台端不再自行重算。
- 原始 `年齡` 欄逐列不變，長表與來源仍然對得起來。

**Non-Goals:**

- **不修改 `年齡` 欄。**
- **不用布林旗標。** 見決策 2。
- **不為其他欄位新增衍生欄位。** 已逐欄掃過 26 個欄位兩輪（相異值判準、眾數佔比判準），只有 `年齡` 有此問題。
- 不改動 summary 與 votes 兩張長表。
- 不改變名錄與圖表的任何顯示結果。

## Decisions

### 1. 乾淨的值放在 `年齡`，來源原值退居 `年齡_原始`

- **Rationale（修正後）:** 本節原本的決定是「原欄位 `年齡` 保留、另加 `年齡_有效`」。**那個設計只開了安全通道，沒有封閉陷阱。** 不讀文件的分析者第一直覺永遠是 `AVG(年齡)`——`年齡` 這個名字有最強的預設吸引力，而它裡面有 483 個哨兵值。要求使用者先讀文件才知道該用另一個欄位，是把責任推給使用者。
- **Decision:** 對調。`年齡` 存放**經過校正、對分析安全**的值（有記載放值、未記載留空）；來源原值完整保留在 `年齡_原始`，緊接其後。
- **確立的新慣例：最直覺的欄位名，必須存放對分析最安全的資料。** 這與專案原本「原欄位＝來源原樣」的慣例相反，但原本那條慣例本來就不是普遍成立的——`elected_authoritative` 存在的理由正是 `當選` 不可信，而文件「要席次請用 `elected_authoritative`」這條指示同樣依賴讀者讀文件，2005 少 19 席正是**依賴讀文件不夠**的教訓。
- ⚠️ **代價一：建置端會出現兩種答案。** 讀來源 CSV 時 `r[10]` 是原值，輸出字典的鍵 `年齡` 卻是乾淨值。除非程式碼保持嚴格的階段邊界，內部很容易踩坑。因此組裝處必須同時寫出兩個鍵、且乾淨值一律經 `valid_age()`，不得直接引用 `r[10]`。
- ⚠️ **代價二：同名欄位的靜默語意變更。** `年齡` 這一欄已存在於版控中的 CSV 且含哨兵值；對調後同一個檔案、同一個欄名在不同 git 修訂版之間代表不同的東西，而且不會有任何錯誤訊息告訴下游。這與本變更所修的 bug 是同一種形狀。接受這個代價的理由是：本資料集只在 repo 內、沒有正式版本號，且這是一次性的、有文件記載的破壞；不接受的代價是永久保留一個會安靜算錯的預設欄位。
- `當選`／`elected_authoritative` 是否比照對調，**不在本變更範圍**，另開變更處理。

### 2. 不用布林旗標（`年齡` 放值，不放 true／false）

- **Rationale:** 若 `年齡` 放 `true`／`false` 之類的旗標，分析者必須**先知道有那一欄**才會去過濾；不知道的人照樣拿到被污染的結果——那正是本變更要解決的情境，等於沒解決。放值或留空才是「直接用就對了」。
- **Decision:** 放值，不放布林。

### 3. 判準與站台端一致，且只有一個實作

- **Rationale:** 同一個規則出現兩份實作，其中一份必然漂移——這正是前兩個變更修掉的兩個 bug 的共同形狀（名錄的 `MAIN` 手寫一份、政黨分桶只認一種名稱）。
- **Decision:** 判準寫在建置端：`0` 在任何屆別都是未記載（不可能是真實年齡）；`99` 只在具名的五個屆別是未記載（它落在合法年齡值域內）。站台的 `build_site_data.py` 改為**讀取**已清乾淨的 `年齡`，刪除自己那份 `AGE_UNRECORDED_TERMS` 與 `display_age` 的推導邏輯，且**不讀** `年齡_原始`——讀了就等於有第二份判準。
- ⚠️ 站台端原有的兩條中止斷言（列入的屆別只允許無資料值、清單外不得出現哨兵）**移到建置端**，不是刪掉。它們守的是「具名清單的前提仍然成立」，那個責任隨判準一起移動。

### 4. 兩個欄位都必須進 oracle 清單

- **Rationale:** 本專案的 `check_manifest` 要求每個輸出欄位都有具名的 provenance／structure／semantic 條目。沒有條目的欄位會讓該檢查失敗——這是刻意的，避免欄位在沒人描述其語意的情況下被加進去。
- **Decision:** `年齡` 的條目改為 `provenance="project"`（它現在是衍生欄位），note 寫明判準、空字串的意義、以及「乾淨不等於正確」；新增 `年齡_原始` 條目，`provenance="official"`，note 指向 `年齡`。

## Implementation Contract

**In scope:** 長表建置腳本的欄位對調與判準、oracle 清單條目、其迴歸測試、站台產生器改為讀取新欄位並移除重複實作、資料集說明文件與專案說明文件的欄位敘述。

**Out of scope:** `年齡` 欄本身、summary 與 votes 兩張長表、其他欄位的衍生欄位、名錄與圖表的顯示結果。

- **Observable behavior:**
  - 候選人長表有 29 個欄位：`年齡` 存放乾淨值，`年齡_原始` 緊接其後存放來源原值。
  - 五個舊屆的 `年齡` 全為空字串；2009-2010 以後四屆的 `年齡` 與 `年齡_原始` 逐列相同。
  - 對 `年齡` 聚合得到 n=7,335、平均 50.80——**不讀文件也拿得到正確答案**。
  - 名錄與圖表的顯示與本變更前完全相同。
- **Interface / data shape:**
  - 候選人長表新增一欄。`年齡` 為數字字串或空字串（乾淨值），`年齡_原始` 為來源原值。
  - `年齡_原始` 的內容逐列等於本變更前的 `年齡` 欄。
  - 站台產生器不再定義 `AGE_UNRECORDED_TERMS`／`AGE_ALWAYS_NO_DATA`／`display_age`，直接讀取 `年齡`（已是乾淨值），不讀 `年齡_原始`。
- **Failure modes:**
  - 具名為未記載的屆別出現第三種值（非 `0` 非 `99`）→ 建置中止，訊息含屆別與該值。
  - 未具名的屆別出現 `99` → 建置中止，訊息含屆別。
  - `年齡` 或 `年齡_原始` 未列入 oracle 清單 → `check_manifest` 失敗。
- **Acceptance criteria:**
  - 重建後 `年齡_原始` 逐列等於重建前的 `年齡`；summary 與 votes 兩張長表 SHA-256 相同。
  - `pytest` 通過；站台 `--check` 通過且兩個 HTML 位元組不變。
  - 站台變異測試全部被偵測到，含移到建置端的兩條斷言各一項變異。
  - 以指令對 `年齡` 聚合，斷言 n=7,335、平均 50.80。

## Risks / Trade-offs

- **需要重建候選人長表。** 這是本變更唯一會改動 `data/processed/` 的部分。必須逐列驗證 `年齡_原始` 等於原本的 `年齡`，否則就是弄丟了來源值——那是本專案最不能犯的錯。
- **兩張表的欄位數不同步。** summary 與 votes 沒有年齡欄，不受影響；但候選人長表的欄位數由 28 變 29，任何以位置索引讀取該表的下游都會錯位。本專案內部都以欄名讀取，外部使用者則以標頭列為準。
- **判準搬家期間有一段兩邊都存在的狀態。** 實作順序必須是「建置端先有欄位並通過驗證，站台端才改為讀取」，否則站台會讀到不存在的欄位。這在任務順序中已固定。
- **`年齡` 現在是衍生欄位，不是來源原樣。** 它只保證「不含哨兵值」，**不保證年齡正確**——來源記載的年齡本身正確與否，本專案未查證也無從查證。這一點須寫進 oracle 條目的 note，避免被讀成資料品質背書。

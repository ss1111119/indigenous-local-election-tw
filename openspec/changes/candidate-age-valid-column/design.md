## Context

候選人長表的 `年齡` 欄在 1994、1998、2002、2005、2006 五屆整批是 `99`（483 列）。那是來源格式文件明列的無資料值——壓縮檔內的 `votedata/voteData/選舉資料庫格式.odt` 對 elcand.csv 寫著「年齡 Num(3) (部分選舉未必有資料，可能 0 或 99)」。本專案不覆寫來源值，所以長表維持 `99`。

前一個變更 `age-99-is-unrecorded` 已在站台呈現端處理，但那層保護只在站台之內。直接使用長表的人拿不到：對 `年齡` 跑 `AVG()`，實測平均由 **50.80**（n=7,335）被拉高到 **53.78**（n=7,818），差 **2.98 歲**，沒有任何錯誤訊息。

本專案對同類情況已有既定做法——原欄位保留、另加一個可用的衍生欄位：

| 原欄位 | 衍生欄位 | 不可用時 |
| --- | --- | --- |
| `縣市` | `縣市_正規化` | 留空 |
| `鄉鎮市區` | `鄉鎮市區_正規化` | 留空 |
| `當選註記` | `elected_authoritative` ＋ `_basis` | 不適用 |

`年齡` 沒有跟上。

## Goals / Non-Goals

**Goals:**

- 直接使用長表的人有一個可以放心聚合的年齡欄位。
- 未記載的判準只有一個實作，站台端不再自行重算。
- 原始 `年齡` 欄逐列不變，長表與來源仍然對得起來。

**Non-Goals:**

- **不修改 `年齡` 欄。**
- **不用布林旗標。** 見決策 2。
- **不為其他欄位新增衍生欄位。** 已逐欄掃過 26 個欄位兩輪（相異值判準、眾數佔比判準），只有 `年齡` 有此問題。
- 不改動 summary 與 votes 兩張長表。
- 不改變名錄與圖表的任何顯示結果。

## Decisions

### 1. 新增 `年齡_有效`，放值或留空

- **Rationale:** 與 `縣市_正規化`／`鄉鎮市區_正規化` 同一個慣例：空字串代表「這一列沒有可用的值」。CSV 的空欄位在 pandas 與多數 SQL 載入器中會成為 NULL／NaN，聚合函數自動略過。
- **Decision:** 欄位名為 `年齡_有效`，緊接在 `年齡` 之後。有記載時放與 `年齡` 相同的值，未記載時放空字串。

### 2. 不用布林旗標

- **Rationale:** 若 `年齡_有效` 放 `true`／`false`，分析者必須**先知道有這一欄**才會去過濾；不知道的人照樣對 `年齡` 跑 `AVG()` 拿到被污染的結果——那正是本變更要解決的情境，等於沒解決。放值或留空則是「用這一欄就對了」，名稱本身就是指示。
- **Decision:** 放值，不放布林。

### 3. 判準與站台端一致，且只有一個實作

- **Rationale:** 同一個規則出現兩份實作，其中一份必然漂移——這正是前兩個變更修掉的兩個 bug 的共同形狀（名錄的 `MAIN` 手寫一份、政黨分桶只認一種名稱）。
- **Decision:** 判準寫在建置端：`0` 在任何屆別都是未記載（不可能是真實年齡）；`99` 只在具名的五個屆別是未記載（它落在合法年齡值域內）。站台的 `build_site_data.py` 改為**讀取** `年齡_有效`，刪除自己那份 `AGE_UNRECORDED_TERMS` 與 `display_age` 的推導邏輯。
- ⚠️ 站台端原有的兩條中止斷言（列入的屆別只允許無資料值、清單外不得出現哨兵）**移到建置端**，不是刪掉。它們守的是「具名清單的前提仍然成立」，那個責任隨判準一起移動。

### 4. `年齡_有效` 必須進 oracle 清單

- **Rationale:** 本專案的 `check_manifest` 要求每個輸出欄位都有具名的 provenance／structure／semantic 條目。沒有條目的欄位會讓該檢查失敗——這是刻意的，避免欄位在沒人描述其語意的情況下被加進去。
- **Decision:** 新增條目，`provenance="project"`（本專案衍生，非來源原生），並在 note 中寫明判準與空字串的意義，比照 `鄉鎮市區_正規化` 的寫法。

## Implementation Contract

**In scope:** 長表建置腳本的欄位新增與判準、oracle 清單條目、其迴歸測試、站台產生器改為讀取新欄位並移除重複實作、資料集說明文件與專案說明文件的欄位敘述。

**Out of scope:** `年齡` 欄本身、summary 與 votes 兩張長表、其他欄位的衍生欄位、名錄與圖表的顯示結果。

- **Observable behavior:**
  - 候選人長表有 29 個欄位，`年齡_有效` 位於 `年齡` 之後。
  - 五個舊屆的 `年齡_有效` 全為空字串；2009-2010 以後四屆與 `年齡` 逐列相同。
  - 對 `年齡_有效` 聚合得到 n=7,335、平均 50.80。
  - 名錄與圖表的顯示與本變更前完全相同。
- **Interface / data shape:**
  - 候選人長表新增一欄，欄名 `年齡_有效`，值為數字字串或空字串。
  - `年齡` 欄的內容與位置不變。
  - 站台產生器不再定義 `AGE_UNRECORDED_TERMS`／`AGE_ALWAYS_NO_DATA`／`display_age`，改為讀取 `年齡_有效`，並將該欄加入必要欄位宣告。
- **Failure modes:**
  - 具名為未記載的屆別出現第三種值（非 `0` 非 `99`）→ 建置中止，訊息含屆別與該值。
  - 未具名的屆別出現 `99` → 建置中止，訊息含屆別。
  - `年齡_有效` 未列入 oracle 清單 → `check_manifest` 失敗。
- **Acceptance criteria:**
  - 重建後 `年齡` 欄逐列與重建前相同；summary 與 votes 兩張長表 SHA-256 相同。
  - `pytest` 通過；站台 `--check` 通過且兩個 HTML 位元組不變。
  - 站台變異測試全部被偵測到，含移到建置端的兩條斷言各一項變異。
  - 以指令對 `年齡_有效` 聚合，斷言 n=7,335、平均 50.80。

## Risks / Trade-offs

- **需要重建候選人長表。** 這是本變更唯一會改動 `data/processed/` 的部分。必須逐列驗證 `年齡` 欄未變，否則就是覆寫了來源值——那是本專案最不能犯的錯。
- **兩張表的欄位數不同步。** summary 與 votes 沒有年齡欄，不受影響；但候選人長表的欄位數由 28 變 29，任何以位置索引讀取該表的下游都會錯位。本專案內部都以欄名讀取，外部使用者則以標頭列為準。
- **判準搬家期間有一段兩邊都存在的狀態。** 實作順序必須是「建置端先有欄位並通過驗證，站台端才改為讀取」，否則站台會讀到不存在的欄位。這在任務順序中已固定。
- **`年齡_有效` 這個名稱的「有效」帶價值判斷。** 它指的是「有記載因而可用於計算」，不是「這個年齡是正確的」——來源記載的年齡本身正確與否，本專案未查證，也無從查證。這一點須寫進 oracle 條目的 note，避免被讀成資料品質背書。

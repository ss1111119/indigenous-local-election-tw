## Context

候選人長表目前有四個與「是否當選」有關的欄位：

| 欄位 | 內容 | 值 |
| --- | --- | --- |
| `當選註記` | **來源原樣** | `*` 4,131／空白 3,609／`!` 42／`-` 36 |
| `當選註記語意` | 上欄的解碼，忠於來源 | 當選／未當選／婦女保障當選／因婦女保障被排擠未當選 |
| `當選` | 由 `當選註記` 推導（`*` 或 `!` → `Y`） | `Y` 4,173／`N` 3,645 |
| `elected_authoritative` | 由 `elctks` 跨檔推導的權威值 | `true` 4,192／`false` 3,626 |
| `elected_authoritative_basis` | 權威值取自 `elctks` 的哪一層 | 選舉區 7,081／鄉鎮市區 727／檔別合計 10 |

`當選` 與權威值有 **63 筆**不符（2005 T2 33 筆、2005 T3 28 筆、1994 T-COMBO 2 筆），全部已逐一具名於 `KNOWN_ELECTED_MARK_ANOMALIES`。以 `當選` 計席次，2005 山原少 12 席、平原少 7 席。

`candidate-age-valid-column` 已確立的慣例是「最直覺的欄位名，必須存放對分析最安全的資料」。`當選` 違反它。

## Goals / Non-Goals

**Goals:**

- 不讀文件的分析者用 `當選` 就得到正確席次。
- 同一事實不要有兩份來源。
- 那 63 筆具名異常**仍然被偵測到**。

**Non-Goals:**

- **不改變 `Y`／`N` 編碼。** 見決策 2。
- **不新增 `當選_原始`。** 見決策 3。
- 不改動 `當選註記` 與 `當選註記語意`。
- 不改動 summary 與 votes 兩張長表，不改變站台顯示結果。

## Decisions

### 1. `當選` 改存權威值，`elected_authoritative` 移除

- **Rationale:** 兩欄的值在對調後完全等價，留著就是同一事實的兩份來源——那正是本專案在 `fix-party-bucket-drift`（名錄的 `MAIN` 手寫一份）與 `candidate-age-valid-column`（站台自己重算判準）修過兩次的病。
- **Decision:** `當選` 存放權威值；`elected_authoritative` 自長表移除。`elected_authoritative_basis` 更名為 `當選_依據`，內容不變——它記錄權威值取自哪一層，是**依據**而非重複，必須保留（727 筆取自鄉鎮市區層級，依據較弱）。

### 2. 維持 `Y`／`N` 編碼，不改成 `true`／`false`

- **Rationale:** 同時改語意與編碼會讓靜默破壞最大化——依欄名讀取的消費者會同時拿到不同的值**與**不同的形式。維持編碼至少讓「型別」這一層不變。
- 另一個理由是這次對調**正好消除**了一個既有的陷阱：`當選` 是 `Y`／`N`、權威值是 `true`／`false`，兩欄直接用 `==` 比較必然全部不相等。本專案曾因此得出「7,818 筆全部不一致」的假結果。移除 `elected_authoritative` 之後，`true`／`false` 這個形式從這個概念中消失，該陷阱不再存在。
- **Decision:** `當選` 維持 `Y`／`N`。

### 3. 不新增 `當選_原始`

- **Rationale:** 與 `candidate-age-valid-column` 不同——那次的 `年齡` 欄**本身就是**來源原值，沒有其他欄位承載它，所以必須另立 `年齡_原始`。這次的 `當選` 本來就是推導欄；來源原樣是 `當選註記`，解碼後是 `當選註記語意`，兩者都完整保留在長表中。再加 `當選_原始` 會是同一事實的第三份表述。
- **Decision:** 不新增。要「來源怎麼寫」的人讀 `當選註記`；要「來源的當選與否」的人讀 `當選註記語意`（`當選` 與 `婦女保障當選` 兩值即為來源認定的當選）。

### 4. ⚠️ 補償檢查必須改為比對「來源推導值 vs 權威值」，否則會靜默失效

- **Rationale:** 這是本變更**最容易出錯的一點**。現行的補償檢查比對 `elected_authoritative` 與 `當選`；`當選` 改存權威值之後，該比對變成「權威值 vs 權威值」，**永遠相等**，那 63 筆具名異常再也不會被偵測到——而且不會有任何錯誤訊息。`KNOWN_ELECTED_MARK_ANOMALIES` 這份具名清單會變成一段沒有資料在測它的死碼。
- **Decision:** 檢查改為比對「由 `當選註記` 推導的值」與「權威值」：`(c["當選註記"] in ELECTED_MARKS) != (c["當選"] == "Y")`。推導所用的 `ELECTED_MARKS` 是既有常數，不新增第二份判準。
- **必須配一項變異**：把檢查改回比對兩個權威值，測試必須失敗。這一項的辨識力來自真實資料（那 63 筆就在資料裡），不需要合成資料。

## Implementation Contract

**In scope:** 長表建置腳本的欄位與補償檢查、oracle 清單、其測試與變異測試、站台產生器與其測試變異、資料集說明文件與專案說明文件。

**Out of scope:** `當選註記`／`當選註記語意`、summary 與 votes 兩張長表、站台的顯示結果、`KNOWN_ELECTED_MARK_ANOMALIES` 的內容（63 筆不變）。

- **Observable behavior:**
  - 對 `當選` 計席次得到正確結果：2005 T2 27 席、T3 30 席（本變更前以 `當選` 計為 20 與 18）。
  - 長表不再有 `elected_authoritative` 欄；`當選_依據` 取代 `elected_authoritative_basis`。
  - 站台的顯示與本變更前完全相同。
- **Interface / data shape:**
  - `當選`：`Y`／`N`，內容等於本變更前的 `elected_authoritative`（`true`→`Y`）。
  - `當選_依據`：內容等於本變更前的 `elected_authoritative_basis`。
  - 欄位數 29 → 28。
- **Failure modes:**
  - 補償檢查在 63 筆之外出現不符即中止，訊息含屆別、選舉種類、候選人與註記。
  - 站台缺 `當選` 欄即中止（既有的缺欄檢查涵蓋）。
- **Acceptance criteria:**
  - `當選` 逐列等於本變更前的 `elected_authoritative`（編碼換算後）；`當選_依據` 逐列相同。
  - `當選註記` 與 `當選註記語意` 逐列不變；summary 與 votes 兩張表 SHA-256 不變。
  - `pytest` 通過；站台 `--check` 通過且兩個 HTML 位元組不變。
  - 變異「補償檢查改回比對兩個權威值」**必須被偵測到**。
  - 以指令對 2005 兩檔用 `當選` 計席次，斷言得到 27 與 30。

## Risks / Trade-offs

- ⚠️ **補償檢查靜默失效是本變更的主要風險**，見決策 4。它不會報錯，只會讓一項驗證從此不再有辨識力，而那項驗證守的正是這次要修的 63 筆。
- **移除欄位會弄斷依欄名讀取 `elected_authoritative` 的消費者。** 這是刻意的——那是本專案唯一能給下游的「大聲的失敗」。相對地，`當選` 的語意變更對依欄名讀取者是**靜默**的（與 `年齡` 那次相同），只能靠文件記錄。
- **`當選` 在不同 git 修訂版之間代表不同的東西。** 與 `年齡` 那次同一種代價，理由與處置也相同：記錄在具名瑕疵與說明文件中。
